## معرفی

«سایه» رباتی است که به شما امکان می‌دهد با افراد ناشناس به‌صورت امن و
خصوصی گفتگو کنید. نام «سایه» برگرفته از مفهوم ناشناسی است — مانند سایه،
حضور دارید اما هویت شما پنهان می‌ماند.

این پروژه با هدف ارائه‌ی یک محصول **Enterprise-level** طراحی شده است:

- **معماری تمیز (Clean Architecture)** با تفکیک کامل لایه‌ها
- **تزریق وابستگی (DI)** برای تست‌پذیری و انعطاف‌پذیری
- **امنیت چندلایه‌ای** — ضد اسپم، Flood، تشخیص رفتار مشکوک
- **حریم خصوصی** — محتوای پیام‌ها هرگز ذخیره نمی‌شود
- **کاملاً رایگان** — بدون نیاز به هیچ سرویس پولی
- **قابل توسعه** — افزودن زبان، دستاورد یا ویژگی جدید آسان است

## ویژگی‌ها

### سیستم ثبت‌نام و پروفایل
- ثبت‌نام چندمرحله‌ای با اعتبارسنجی کامل
- نام مستعار، بیو، جنسیت، سن، کشور، زبان، علایق
- تصویر پروفایل
- تنظیمات حریم خصوصی (نمایش/پنهان سن، کشور، جنسیت)

### جستجوی مخاطب هوشمند
- جستجوی تصادفی
- فیلتر بر اساس جنسیت، کشور، زبان، بازه سنی، علایق
- **الگوریتم Matchmaking** با امتیازدهی چندفاکتوری
- جلوگیری از اتصال مجدد به شرکای اخیر
- سیستم صف انتظار با timeout
- توزیع عادلانه (اولویت به قدیمی‌ترین در صف)

### امکانات گفتگو
- ارسال تمام انواع پیام: متن، عکس، ویدیو، فایل، ویس، موزیک، استیکر، گیف، Video Note، Location، Contact، Poll
- آلبوم (Media Group)
- Reply و Forward
- نشانگر «در حال تایپ» (Chat Action)
- پایان گفتگو، پیدا کردن فرد جدید
- گزارش مخاطب، افزودن به محبوب‌ها
- امتیازدهی به گفتگو

### امنیت
- **Rate Limiting** (Sliding Window)
- **تشخیص Flood** (پیام تکراری پشت سر هم)
- **امتیاز ریسک** کاربران (الگوریتم چندفاکتوری)
- **بن خودکار** در صورت عبور از آستانه‌ی ریسک یا گزارش
- بن موقت و دائم
- پاک‌سازی خودکار بن‌های منقضی
- جلوگیری از SQL Injection و XSS
- ماسک کردن داده‌ی حساس در لاگ‌ها

### پنل مدیریت
- داشبورد آمار实时
- مدیریت کاربران (جستجو، مشاهده، بن/آن‌بن/بلاک)
- صف بررسی گزارش‌ها
- ارسال پیام همگانی و هدفمند
- فعال‌سازی حالت نگهداری (Maintenance Mode)
- مشاهده لاگ‌های امنیتی و حسابرسی

### سیستم اجتماعی و گیمیفیکیشن
- **Referral System** با لینک دعوت اختصاصی
- پاداش XP برای دعوت موفق
- **پاداش روزانه** ورود
- **دستاوردها (Achievements)** — ۸ دستاورد پیش‌فرض
- سیستم **سطح و XP**
- **جدول رتبه‌بندی** (Leaderboard)

### سیستم آمار
- تعداد کاربران، آنلاین، فعال امروز
- تعداد گفتگوهای فعال
- میانگین مدت گفتگو
- تعداد گزارش‌ها و بن‌ها
- رشد کاربران (روزانه)

### زیرساخت
- **SQLite** به‌صورت پیش‌فرض (قابل ارتقا به PostgreSQL با تغییر یک خط)
- **Alembic** برای مهاجرت‌های دیتابیس
- **Structured Logging** با structlog (JSON / Console)
- **Background Jobs** با APScheduler
- **Health Check** HTTP endpoint
- **i18n** — پشتیبانی از فارسی و انگلیسی

## معماری پروژه

این پروژه بر اساس **Clean Architecture** طراحی شده است:

```
┌─────────────────────────────────────────────────────────┐
│                    Handlers (Bot)                        │
│         (رابط کاربری — تلگرام)                           │
├─────────────────────────────────────────────────────────┤
│                    Middlewares                           │
│    (Logging → Maintenance → Ban → RateLimit → DB)       │
├─────────────────────────────────────────────────────────┤
│                    Services                              │
│         (منطق کسب‌وکار — Business Logic)                │
├─────────────────────────────────────────────────────────┤
│                   Repositories                           │
│         (الگوی Repository — دسترسی داده)                │
├─────────────────────────────────────────────────────────┤
│                    Models / DB                           │
│         (SQLAlchemy 2.x — ORM)                          │
├─────────────────────────────────────────────────────────┤
│                    Core / Config                         │
│    (DI Container, Settings, Logging, Security)          │
└─────────────────────────────────────────────────────────┘
```

**اصول طراحی:**
- **SOLID**: هر کلاس یک مسئولیت دارد، وابستگی‌ها معکوس می‌شوند
- **DRY**: کد مشترک در BaseRepository و mixins
- **KISS**: پیچیدگی فقط جایی که لازم است
- **Dependency Injection**: تمام وابستگی‌ها از Container تزریق می‌شوند

## نصب و اجرای محلی

### روش ۱: با Poetry (توصیه‌شده)

```bash
# 1. کلون کردن پروژه
git clone https://github.com/saya-bot/anonchat.git
cd anonchat

# 2. نصب وابستگی‌ها
poetry install

# 3. کپی فایل محیطی و تنظیم
cp .env.example .env
# فایل .env را ویرایش کرده و BOT_TOKEN و ADMIN_IDS را وارد کنید

# 4. اجرای مهاجرت‌ها
poetry run alembic upgrade head

# 5. اجرای ربات
poetry run python -m anonchat.main
```

### روش ۲: با Docker

```bash
# 1. کپی فایل محیطی
cp .env.example .env
# فایل .env را ویرایش کنید

# 2. اجرا با Docker Compose
docker-compose up -d
```

### روش ۳: با pip مستقیم

```bash
python -m venv .venv
source .venv/bin/activate  # در ویندوز: .venv\Scripts\activate
pip install -e .
cp .env.example .env
# ویرایش .env
alembic upgrade head
python -m anonchat.main
```

## متغیرهای محیطی

تمام متغیرها در فایل [`.env.example`](.env.example) توضیح داده شده‌اند.
مهم‌ترین آن‌ها:

| متغیر | اجباری | توضیح |

| `MAINTENANCE_MODE` | ❌ | حالت نگهداری |

## استقرار روی Railway

این پروژه به‌گونه‌ای طراحی شده که **کاملاً روی پلن رایگان Railway** قابل اجرا باشد.

### مراحل

1. **ساخت ربات در BotFather** و دریافت توکن

2. **ساخت پروژه در Railway**
   - به [railway.app](https://railway.app) بروید
   - New Project → Deploy from GitHub repo
   - مخزن خود را انتخاب کنید

3. **تنظیم متغیرهای محیطی** در پنل Railway:
   ```
   BOT_TOKEN=your_bot_token
   ADMIN_IDS=your_telegram_id
   DATABASE_URL=sqlite+aiosqlite:///./data/saya.db
   LOG_FORMAT=json
   HEALTH_PORT=8080
   ```

4. **Railway به‌طور خودکار** فایل `railway.json` را می‌خواند و:
   - Docker image می‌سازد
   - مهاجرت‌ها را اجرا می‌کند
   - Health Check را بررسی می‌کند

5. **اولین استقرار** پس از چند دقیقه کامل می‌شود.

> **نکته:** روی پلن رایگان Railway، پایگاه داده SQLite در volume محلی ذخیره
> می‌شود. برای پروداکشن بزرگ‌تر، می‌توانید از PostgreSQL رایگان
> [Neon](https://neon.tech) یا [Supabase](https://supabase.com) استفاده کنید —
> فقط `DATABASE_URL` را تغییر دهید.

## امنیت

### لایه‌های امنیتی

1. **اعتبارسنجی ورودی** — تمام ورودی‌های کاربر با Pydantic و توابع امنیتی پاک‌سازی می‌شوند
2. **Rate Limiting** — الگوریتم Sliding Window برای جلوگیری از اسپم
3. **تشخیص Flood** — شناسایی پیام‌های تکراری پشت سر هم
4. **امتیاز ریسک** — ترکیب فاکتورهای: گزارش‌ها، بن‌های قبلی، سن حساب، سرعت پیام
5. **بن خودکار** — در صورت عبور از آستانه‌ی ریسک یا تعداد گزارش
6. **حریم خصوصی پیام** — محتوای پیام متنی هرگز ذخیره نمی‌شود (فقط هش و طول)
7. **ماسک در لاگ** — توکن‌ها و داده‌ی حساس در لاگ‌ها ماسک می‌شوند

### نکات امنیتی

- هرگز فایل `.env` را commit نکنید
- توکن ربات را با کسی به اشتراک نگذارید
- شناسه‌ی مدیران را به‌دقت انتخاب کنید
- لاگ‌های امنیتی را به‌طور دوره‌ای بررسی کنید
- برای پروداکشن، `LOG_FORMAT=json` تنظیم کنید

## توسعه‌دهندگان

### اجرای تست‌ها

```bash
poetry run pytest -v
```

### بررسی کیفیت کد

```bash
poetry run ruff check src/ tests/
poetry run ruff format --check src/ tests/
```

### ساخت مهاجرت جدید

پس از تغییر مدل‌ها:

```bash
poetry run alembic revision --autogenerate -m "توضیح تغییر"
poetry run alembic upgrade head
```

### افزودن زبان جدید

1. فایل `src/anonchat/i18n/locales/<code>.json` بسازید (از `fa.json` کپی کنید)
2. کلیدها را ترجمه کنید
3. کد زبان را در `i18n/__init__.py` به `_SUPPORTED_LOCALES` اضافه کنید

### افزودن دستاورد جدید

در `src/anonchat/services/achievement_service.py`، آرایه‌ی `DEFAULT_ACHIEVEMENTS`
را ویرایش کنید و منطق بررسی را در متد `_meets_criteria` اضافه کنید.

## رفع خطا

### ربات روشن نمی‌شود
- بررسی کنید `BOT_TOKEN` صحیح باشد
- بررسی کنید `ADMIN_IDS` حداقل یک شناسه داشته باشد
- لاگ‌ها را در `dev.log` یا خروجی Railway بررسی کنید

### خطای دیتابیس
- برای SQLite: پوشه‌ی `data/` وجود داشته باشد
- برای PostgreSQL: URL را با `postgresql+asyncpg://` شروع کنید
- مهاجرت‌ها را اجرا کنید: `alembic upgrade head`

### ربات پاسخ نمی‌دهد
- بررسی کنید ربات در BotFather فعال باشد
- بررسی کنید `MAINTENANCE_MODE=false` باشد
- بررسی کنید کاربر بن نباشد

### خطای Webhook
- روی پلن رایگان Railway از Long Polling استفاده کنید (`USE_WEBHOOK=false`)
