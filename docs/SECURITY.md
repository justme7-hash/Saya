# راهنمای امنیت

## مدل تهدید

ربات سایه با چند نوع تهدید مقابله می‌کند:

### ۱. اسپم و Flood
- **تهدید**: کاربر پیام‌های زیاد و سریع می‌فرستد
- **دفاع**: Rate Limiting (Sliding Window) + تشخیص Flood
- **پاسخ**: هشدار → بن موقت → بن دائم

### ۲. رفتار سوءاستفاده‌گرانه
- **تهدید**: آزار و اذیت، محتوای نامناسب، کلاهبرداری
- **دفاع**: سیستم گزارش + امتیاز ریسک + بن خودکار
- **پاسخ**: گزارش توسط کاربران → بررسی مدیر → بن

### ۳. تلاش برای نفوذ
- **تهدید**: SQL Injection، XSS، کاراکترهای مخرب
- **دفاع**: پاک‌سازی ورودی + SQLAlchemy parameterized queries
- **پاسخ**: ورودی مخرب حذف/رد می‌شود

### ۴. نشت داده
- **تهدید**: لو رفتن توکن یا داده‌ی حساس در لاگ
- **دفاع**: ماسک خودکار در لاگ + عدم ذخیره‌ی محتوای پیام
- **پاسخ**: توکن در لاگ به‌صورت `123456...xxxx` نمایش داده می‌شود

## لایه‌های امنیتی

### لایه ۱: ورودی
```python
# پاک‌سازی متن
sanitize_text(message.text)

# اعتبارسنجی نام مستعار
sanitize_nickname(nickname)  # ۲-۳۰ کاراکتر، فقط حروف/اعداد

# اعتبارسنجی سن
validate_age(age)  # ۱۳-۱۲۰

# اعتبارسنجی کد کشور
validate_country_code(code)  # ISO 3166-1 alpha-2
```

### لایه ۲: Rate Limiting
- الگوریتم: Sliding Window
- پیش‌فرض: ۲۰ پیام در ۶۰ ثانیه
- قابل تنظیم با `RATE_LIMIT_MESSAGES` و `RATE_LIMIT_WINDOW`

### لایه ۳: تشخیص Flood
- تشخیص: ۵ پیام یکسان در ۱۰ ثانیه
- پاسخ: هشدار + افزایش شمارنده‌ی نقض

### لایه ۴: امتیاز ریسک
فاکتورها:
- گزارش‌های فعال: هر گزارش ۸ امتیاز (حداکثر ۴۰)
- بن‌های قبلی: هر بن ۱۵ امتیاز (حداکثر ۴۵)
- نقض Rate Limit: هر بار ۵ امتیاز (حداکثر ۲۰)
- حساب جدید (< ۳ روز): ۲۰ امتیاز
- سرعت پیام بالا (> ۱۰/دقیقه): ۱۵ امتیاز

اگر امتیاز ≥ ۸۰: بن خودکار موقت (۲۴ ساعت)

### لایه ۵: بن و مسدودسازی
- بن موقت: با تاریخ انقضا
- بن دائم: بدون تاریخ انقضا
- بلاک: قطع دسترسی بدون بن
- پاک‌سازی خودکار بن‌های منقضی (هر ساعت)

### لایه ۶: حریم خصوصی
- محتوای پیام متنی **هرگز** ذخیره نمی‌شود
- فقط متادیتا: نوع، طول، هش (SHA-256، ۳۲ کاراکتر)
- هش فقط برای تشخیص اسپم تکراری استفاده می‌شود
- در صورت گزارش، خلاصه‌ی کوتاه برای بررسی مدیر

### لایه ۷: لاگ‌گذاری امن
- ماسک خودکار توکن و URL دیتابیس
- لاگ‌های امنیتی جداگانه (`security_logs` table)
- لاگ‌های حسابرسی (`audit_logs` table) برای عملیات مدیران

## بهترین روش‌ها برای مدیران

### مدیریت توکن
- توکن را هرگز به اشتراک نگذارید
- اگر لو رفت، در BotFather توکن را reset کنید
- فایل `.env` را هرگز commit نکنید

### مدیریت مدیران
- فقط به افراد مورد اعتماد دسترسی مدیر بدهید
- شناسه‌های مدیر را به‌طور دوره‌ای بررسی کنید
- عملیات مدیران در `audit_logs` ثبت می‌شود

### بررسی گزارش‌ها
- گزارش‌های در انتظار را به‌موقع بررسی کنید
- قبل از بن، تاریخچه‌ی کاربر را بررسی کنید
- در صورت اشتباه، با `/unban` بن را لغو کنید

### حالت نگهداری
- هنگام به‌روزرسانی یا تعمیر، `MAINTENANCE_MODE=true` کنید
- فقط مدیران می‌توانند استفاده کنند
- پس از اتمام، حتماً غیرفعال کنید

## بررسی امنیتی دوره‌ای

### روزانه
- بررسی گزارش‌های در انتظار
- بررسی بن‌های اخیر
- بررسی خطاهای امنیتی در لاگ

### هفتگی
- بررسی کاربران با امتیاز ریسک بالا
- پاک‌سازی لاگ‌های قدیمی
- بررسی آمار اسپم/Flood

### ماهانه
- بررسی لیست مدیران
- تغییر توکن (در صورت نیاز)
- به‌روزرسانی وابستگی‌ها

## آسیب‌پذیری‌های شناخته‌شده

### محدودیت Bot API تلگرام
- **تایپ‌کردن**: Bot API فقط `send_chat_action` را پشتیبانی می‌کند (نه تایپ real-time)
- **ویرایش پیام**: امکان ویرایش پیام ارسال‌شده به شریک وجود ندارد
- **حذف پیام**: ربات می‌تواند پیام خود را حذف کند، نه پیام کاربر را

### راهکارها
- برای تایپ‌کردن: `send_chat_action("typing")` قبل از رله
- برای ویرایش: قابلیت موجود نیست
- برای حذف: ربات پیام رله‌شده را مال خود می‌داند و می‌تواند حذف کند

## گزارش آسیب‌پذیری

اگر آسیب‌پذیری امنیتی پیدا کردید:
1. آن را به‌صورت عمومی منتشر نکنید
2. به ایمیل `security@saya-bot.ir` گزارش دهید
3. جزئیات و راهکار پیشنهادی را ارسال کنید
4. ظرف ۴۸ ساعت پاسخ دریافت می‌کنید
